## 3. ארכיטקטורה וסטאק

### 3א. התמונה הכללית

```
 Alpaca IEX ws ─┐                                   (one upstream connection per SERVER,
 Finnhub ws  ───┼─► MarketDataHub ──► Queue[Tick|Bar]  symbols = union of all users' watchlists)
 yfinance poll ─┘                          │
 Daily history (REST, cached in DB) ──► MarketState per symbol
                                       (daily closes, today's running O/H/L/C,
                                        current 1-min candle built from ticks, intraday peak)
                                           │ every tick
                                           ▼
                                     MetricsEngine ──► InsightEngine (fixed catalogue, per symbol)
                                           │                 │
                                           ▼                 ▼
                                AlertEngine (per user, user-defined rules incl. "my rule")
                                           │
                                           ▼
                                Notifier (interface) ─► TelegramNotifier (async queue)
 Broadcaster ─► per-user websocket fan-out (each client gets only its symbols) ─► PWA
 DB (SQLAlchemy): users · watchlist_items · alerts · alert_events · insight_settings · daily_bars
```

### 3ב. "זמן אמת" בפועל (החלטה 1)

- **כל tick, מיד:** המחיר האחרון מתעדכן. הנר של הדקה הנוכחית נבנה בשרת מה-ticks, ונשלח לדפדפן, שמבצע `series.update()`. כשמגיע ה-bar הרשמי של הדקה מ-Alpaca, הוא מיישר את הנר.
- **מדדים ותובנות בכל tick:** חלון של 252 ימים הוא מערך numpy קטן.
  - **[הסקה]** החישוב לוקח מיקרו-שניות עד בודדות מילי-שניות לסימבול, ולכן אין צורך ב-throttle.
  - **coalescing כרשת ביטחון בלבד:** אם מגיעים יותר מ-20 עדכונים בשנייה לסימבול, נשלח רק האחרון בכל 50ms. העין לא תבחין.
- **המגבלה האמיתית היא הנתונים:** ב-IEX מניה פחות סחירה יכולה לקבל עסקה רק כל כמה שניות, ולכן "רציף" הוא רציף כמו ה-feed.
  - **[לא אומת]** אם ערוץ ה-quotes (bid/ask) נספר בנפרד במגבלת 30 הסימבולים, אפשר להוסיף אותו לעדכונים תכופים יותר. לבדיקה בשלב 4.
- **סימון טריות:** כל שורה מציגה "עודכן לפני X שניות", ו"נתון לא טרי" מעל 60 שניות בשעות מסחר.

### 3ד. החלטות טכניות

1. **בלי SDK של ספקים.** רק `websockets` ו-`httpx`.
   - `StockDataStream` של alpaca-py מריץ לולאה משלו **[מזיכרון]**.
   - הפרוטוקולים של Alpaca ו-Finnhub הם JSON פשוט, כ-60-80 שורות לספק.
2. **טלגרם:** `python-telegram-bot`, רק `Bot` לשליחה בתוך ה-lifespan, עם `await`. אין `Application` ואין polling, ולכן אין לולאה שנייה. זה מתקן גם את באג ה-`await` של אב-הטיפוס.
   - ההודעות עוברות בתור, בקצב של עד הודעה לשנייה לצ'אט **[מזיכרון]**.
3. **זמן:**
   - הכול בשעון ניו יורק (`zoneinfo`), ו-`tzdata` נדרש ב-Windows **[מזיכרון]**.
   - שעת הפתיחה בישראל זזה בין 16:30 ל-15:30 בגלל שעון קיץ שמתחלף בתאריכים שונים.
4. **רשת ואבטחה:**
   - ברירת מחדל `127.0.0.1`.
   - מצב LAN: `0.0.0.0` עם token, ופתיחה ב-Windows Firewall באישור Roy.
   - הסודות רק ב-`.env`, והלוגים בלי סודות (נבדק בטסט).
5. **הרצה:** דרך `.venv\Scripts\python.exe -m ...`, בלי activate, כדי לא לשנות את ExecutionPolicy.

### 3ה. ממשק הספק (העוגן להחלפה בספק מסחרי)

```python
# riskbro/providers/base.py
@dataclass(frozen=True)
class Bar:  symbol: str; ts: datetime; open: float; high: float; low: float; close: float; volume: float
@dataclass(frozen=True)
class Tick: symbol: str; ts: datetime; price: float; size: float; source: str

class MarketDataProvider(Protocol):
    name: str                  # "alpaca-iex", "finnhub", "yahoo-delayed", later "licensed-vendor"
    is_realtime: bool
    licence: str               # "personal-only" | "redistribution" -> app refuses multi-user mode with personal-only
    max_stream_symbols: int
    async def get_daily_bars(self, symbol: str, start: date, end: date) -> list[Bar]: ...  # adjusted
    async def get_intraday_bars(self, symbol: str, day: date) -> list[Bar]: ...
    def stream(self, symbols: set[str]) -> AsyncIterator[Tick | Bar]: ...                # reconnect + backoff
    async def set_symbols(self, symbols: set[str]) -> None: ...
```

השדה `licence` הוא **בלם בקוד.** אם יש יותר ממשתמש אחד והספק `personal-only`, השרת מסרב לעלות. כך הפרת תנאים לא קורית בטעות.

מימושים: Alpaca, Finnhub, Yahoo, ו-`ReplayProvider`. האחרון מנגן CSV, ומשמש לבדיקות ולמצב הדגמה בלילה.

### 4א. העיקרון
תובנה היא **משפט עובדתי על מה שקרה או קורה בנתונים**, יחד עם **החישוב שמאחוריו.** היא אף פעם לא אומרת מה לעשות.
- הקטלוג קבוע, והפרמטרים זהים לכל המשתמשים: מתועדים, ואפשר לשנות אותם רק בהגדרות האישיות.
- התובנות מוצגות **באפליקציה בלבד** (המשתמש שולף).
- **push לטלגרם** רק לתובנה שהמשתמש בחר והגדיר לה סף בעצמו. מפת הגבול: "התראה יזומה של המערכת עלולה להיחשב המלצה".

### 4ב. מבנה תובנה

```python
@dataclass(frozen=True)
class Insight:
    kind: str                 # from fixed catalogue, e.g. "VOL_RATIO"
    symbol: str
    statement_he: str         # rendered from a fixed template
    statement_en: str
    formula: str              # human-readable, e.g. "vol_10d / vol_30d = 0.412 / 0.179"
    inputs: dict[str, float]  # every number used, shown on "how is this calculated?"
    params: dict[str, float]  # windows/thresholds used (same defaults for every user)
    source: str               # "alpaca-iex (live) + alpaca daily bars"
    asof: datetime
    user_rule_id: int | None = None   # only for RULE_LEVEL: links to the user's own rule
```

**בממשק:** כרטיס לכל תובנה. לחיצה על "איך זה חושב?" פותחת את הנוסחה, את המספרים, את החלון ואת המקור.
- הסדר קבוע: לפי סימבול ואחר כך לפי סוג.
- **אין דירוג, אין "החשובה ביותר", ואין צבעי טוב/רע.**

### 4ג. הקטלוג של גרסה 1

| סוג | דוגמת ניסוח (עובדתי) | חישוב |
|---|---|---|
| `VOL_RATIO` | "התנודתיות ב-10 הימים האחרונים היא פי 2.3 מהתנודתיות של 30 הימים" | `vol(10d) / vol(30d)`, שתיהן שנתיות על log returns וכוללות את המחיר הנוכחי. הניסוח של Roy ("ממוצע 30 יום") מוגדר כך במדויק: החלטה 6 |

| `BETA_CONTEXT` | "ב-252 הימים האחרונים, הבטא מול SPY היא 1.3" | `cov/var` על תשואות פשוטות. **אין** ניסוח פרשני כמו "מסוכנת יותר מהשוק" |

### 4ד. הגנות בקוד (נבדקות אוטומטית)

1. **רשימת מילים אסורות**, בעברית ובאנגלית: `קנה, קנייה, מכור, מכירה, כדאי, מומלץ, המלצה, הזדמנות, כניסה, יציאה, יעד, סטופ, חזק, חלש, קנוי יתר, מכור יתר, buy, sell, should, recommend, opportunity, entry, exit, target, bullish, bearish, oversold, overbought, strong, weak`.
   - טסט סורק את כל התבניות, ואת כל הטקסטים שמופקים בבדיקות, ונכשל אם נמצאה מילה כזו.
   - הרשימה תוחזק יחד עם סוכן המשפט, ותיבדק מול עו"ד (שאלה 5 בדוח המשפט).
2. **`formula` ו-`inputs` לא ריקים** לכל תובנה (טסט).
3. **"זהה לכל משתמש":** שני משתמשים עם אותה רשימה ואותם פרמטרים מקבלים תובנות זהות, חוץ מ-`RULE_LEVEL` (טסט).
4. **אין תובנה בלי נתונים מספיקים.** במקום ניחוש מוצג "אין מספיק היסטוריה".
5. **תובנה חדשה = שינוי בקוד, עם סקירה מול מפת הגבול.** אין תבניות דינמיות, ואין AI שמנסח בגרסה 1.

## 5. המדדים: ההגדרות המדויקות

כל המדדים מחושבים על **תשואות** או על **יחס למחיר**, ולעולם לא על רמת המחיר (הבאג של אב-הטיפוס).

| מדד | הגדרה | "חי" |
|---|---|---|
| תשואה | `r_t = ln(P_t / P_{t-1})` על סגירה מתואמת. לבטא ול-`DROP_COUNT`: תשואה פשוטה | המחיר האחרון הוא "סגירה זמנית" של היום |
| תנודתיות שנתית | `std(r, ddof=1) * sqrt(252)` על N התשואות האחרונות (ברירת מחדל: 10, 20, 30 ו-60) | N-1 תשואות היסטוריות, ועוד תשואת היום הזמנית |
| ירידה מקסימלית לתקופה | `min_t (P_t / max_{s≤t} P_s − 1)`, בחלון של 252 ימים כברירת מחדל | המחיר הנוכחי הוא הנקודה האחרונה |
| ירידה תוך-יומית | נוכחית: `P_now / H_today − 1`. מקסימלית: המינימום שלה מאז הפתיחה | O(1) בכל tick (קירוב על IEX) |
| בטא | `cov(r_s, r_m) / var(r_m)`, תשואות פשוטות, יישור לפי תאריך (inner join), 252 ימים, מול **SPY** (תופס סימבול אחד מ-30) | כולל את התשואה הזמנית של שניהם |
| ATR | `TR = max(H−L, |H−C_prev|, |L−C_prev|)`. ביום הראשון TR = H−L. התחלה: ממוצע N ה-TR הראשונים, ומשם Wilder: `ATR_t = (ATR_{t-1}(N−1) + TR_t)/N`, עם N=14. מוצג גם `ATR% = ATR/P` | TR של היום מה-H/L השוטפים |

## 9. ל-CFO: מה עולה SaaS (נתונים ואחסון)

### 9א. נתוני שוק ל-SaaS (הפצה מסחרית)
